---
name: setup
description: Set up or diagnose Premiere Editor Assistant on a local Mac, including its Premiere bridges and optional transcription dependencies. Use for this plugin’s installation and connection problems.
---

Use this workflow for the Premiere Editor Assistant plugin. Resolve the plugin root from this file: two directories above its containing folder. Run commands using absolute paths and quote paths with spaces.

1. Run `/bin/bash "<plugin-root>/scripts/launch.sh" doctor`. This is a dependency check, not a live Premiere acceptance test. Release 0.1 supports macOS and English editorial input; Apple Silicon is required for optional local MLX transcription. The native workflow was exercised with Premiere 26.3.2; a new host version needs read-only capability checks first.
2. If setup was requested, run `/bin/bash "<plugin-root>/scripts/launch.sh" setup` to download and verify the pinned bridges, install locked JavaScript dependencies, apply the guarded reorder patch, and prepare a CCX installer. It reports its local data directory. The package contains no footage or project configuration.
3. Resolve executable discovery before installing duplicates. The launcher searches common Homebrew and Node version-manager locations and skips unsupported Node versions. Reuse existing compatible Node.js 22+, Python 3.9+, and FFmpeg/ffprobe installations first. Persist custom paths with `launch.sh configure --node "/absolute/node" --python "/absolute/python" --ffmpeg "/absolute/ffmpeg" --ffprobe "/absolute/ffprobe"` (supply only needed options). Settings are local, shared across package versions, and loaded by both bridges and workflow commands. `PREMIERE_ASSISTANT_NODE`, `PREMIERE_ASSISTANT_PYTHON`, `PREMIERE_ASSISTANT_FFMPEG` and `PREMIERE_ASSISTANT_FFPROBE` override saved paths; a Node override can bootstrap configure when Node is not discoverable. Only if a compatible installation is absent, help install through the user’s existing package manager. Do not silently change package-manager configuration. Do not invent direct-download URLs or archive extraction commands; use the package manager or a verified official installer.
4. Install the CEP panel with `setup --install-cep` when needed. This copies the pinned panel and enables Adobe’s unsigned CEP panel preference. A differing existing panel is reported instead of overwritten. Install the generated `premiere-editor-assistant-panel.ccx` through Adobe Creative Cloud, or load the prepared `integrations/quadlzzz/panel/manifest.json` in Adobe UXP Developer Tool. Preserve existing projects before any required Premiere restart. Open Window → Extensions → MCP for Adobe Premiere Pro and Window → UXP Plugins → Premiere MCP Agent.
5. Local transcription is optional. Doctor checks the configured Python, imports MLX Whisper, Torch, Transformers and SentencePiece, and lists older versioned environments as unverified reuse candidates. To reuse one, persist its exact executable with `configure --python "/older/runtime/python/bin/python"`, then rerun doctor. Keep that older directory while referenced; do not copy/move a venv or delete it during an upgrade. Otherwise use `setup --local-models` on Apple Silicon. Model weights download when first used; successful imports do not prove weights or transcription work. Premiere-native transcripts and existing timed transcript files are also supported. ElevenLabs (Scribe) is the ElevenLabs transcription option, not a separate service, and requires the user’s own ElevenLabs credentials and explicit authorization to send the selected audio; keep credentials outside the plugin. Gemini is deferred and is not configured by setup.
6. Open a project in Premiere. Run `doctor` again, then `smoke --live` through the launcher. Required panel checks must pass, including transcript helpers and the current UXP entrypoint. For a UXP Developer Tool installation, set `PREMIERE_ASSISTANT_UXP_PANEL` to the loaded panel directory for doctor. A tool-list handshake alone does not prove Premiere is connected. Report any missing panel or version limitation precisely. The broker listens only on loopback; the shipped Adobe panel expects port 3001.
7. On upgrades, inspect existing user/project MCP startup entries for this plugin before declaring setup complete: old versioned launcher paths and duplicate bundled/manual bridge launches need reconciliation. Prefer the current bundled bridges; preserve intentional tool restrictions and other services. If manual entries are needed, point them at this package's launcher and use one launch per backend. Back up configuration before authorized edits; keep plugin skills enabled. After startup changes, have the user reload connections or restart Codex if automatic reload is unavailable, then verify both bridges with read-only calls from the chat. Direct `smoke --live` does not prove Codex loaded the new configuration. Report reload as pending until confirmed. See the [upgrade checklist](../../INSTALL.md#upgrade-from-an-earlier-version).
8. Choose a working directory for this project, then use organize-project for Project-panel bins and names, edit-video for Takes/Selects, or export-omf for a requested sound handoff. Organization uses the CEP bridge without transcription models. OMF uses the same CEP bridge and standard-library Python helper; it needs no transcription models. Each project keeps its own evidence and journal. Reuse the plugin’s shared runtime across projects.

Runtime data defaults to `~/Library/Application Support/Premiere Editor Assistant/0.1.4` (or the host’s PLUGIN_DATA directory). `PREMIERE_ASSISTANT_DATA` explicitly overrides that location. Package updates must retain project journals and evidence; never clear an uncertain operation to make a retry run.

Executable paths are stored as plain path files under `~/Library/Application Support/Premiere Editor Assistant/executables`; `PREMIERE_ASSISTANT_CONFIG` overrides that directory. They are never sourced as shell code or included in the shared package. Use absolute quoted paths, literal directory enumeration instead of unmatched wildcards, and portable command lookup rather than workstation-specific tool paths. If process inspection is blocked, use the packaged read-only checks and report the limit. If Finder input fails, use the exact installer path reported by setup or the prepared UXP manifest. Do not claim a connection reload, model download, listening, or editorial acceptance from file checks.

Bridge JavaScript dependencies use the public npm registry for this installation only. Set `PREMIERE_ASSISTANT_NPM_REGISTRY` for a managed mirror; setup does not edit global npm settings.

Follow the [retry and recovery procedure](../../INSTALL.md#retries-interruptions-and-alternatives). Rerun the same setup command after transient failure; inspect its JSON result and `setup-status.json` instead of assuming every nonzero result lost the whole installation. Exit 2 means the runtime is prepared with pending CCX or optional local-model work. Preserve the reported data/config/executable paths and any managed-mirror environment. Setup retries recognized temporary download/npm/pip failures at most three times and reuses reverified cached archives and stage checkpoints. Do not add an outer retry loop, bypass checksums, replace differing panels, or clear uncertain locks. A lock with an unknown owner or surviving workers needs reconciliation. Read the reported stage, attempts, log and fallback before choosing the next action.

When a requested optional Whisper installation fails, finish independent essential bridge/panel checks and offer Premiere-native transcription, an existing timed transcript, or explicitly authorized ElevenLabs (Scribe). Never silently change the transcription provider or upload audio. The external provider name `scribe` means ElevenLabs; `existing` is transcript-file reuse. Native transcripts are verified separately, and external results are imported back into Premiere. Failed CCX generation/installation can use the prepared UXP manifest through Adobe UXP Developer Tool, followed by doctor and read-only live checks. A failed Codex reload remains pending for the user; repeating UI automation is not proof of completion. Setup/read-only connection retries must never replay editorial mutations or paid transcription requests.
